# PC仲裁员端重构 - 第一阶段设计规范（整体框架与首页功能区）

## 1. 概述 (Overview)

本文档定义了“PC仲裁员办案系统重构”第一阶段（P0级）的详细设计规范。本阶段聚焦于**系统全局路由框架**与**首页核心信息看板**的构建，旨在为仲裁员提供一个专业、克制且高效的日常工作台。

## 2. 技术栈与架构 (Tech Stack & Architecture)

*   **前端框架**：Vue 3
*   **UI 组件库**：Element Plus
*   **CSS 方案**：基础 SCSS / CSS 配合 Element Plus CSS Variables 主题定制（**禁用 Tailwind 等 Utility-first CSS 库**，以确保代码风格统一和视觉克制）。
*   **图标系统**：Element Plus 内置图标库为主，辅助使用 `@iconify/vue` 提供的线性单色图标。

## 3. 视觉基调与设计约束 (Visual Guidelines & Constraints)

遵循“企业/政务级”系统的严谨性，摒弃过度设计的“AI感”。

*   **核心背景色**：页面底层使用中性浅灰 `#F0F2F5` 或 `#F5F7FA`。
*   **品牌色系**：
    *   **主题色 (Primary)**：`#053d99`，用于当前状态高亮、主操作按钮及关键数据标记。
    *   **深色 (Dark)**：`#00296b`，用于重点文字、交互悬浮态或需强化的标题。
    *   **辅助色 (Light/Secondary)**：`#f2f5fa`，用于浅色背景区块或次要状态高亮。
*   **组件容器**：所有信息卡片（Widget）采用纯白背景 `#FFFFFF`。
*   **边框与阴影约束**：
    *   卡片边界使用 1px 极浅边框 `#E4E7ED`，圆角 4px。
    *   **严格禁止**：大面积模糊背景、发光描边、高饱和渐变色按钮。
    *   **阴影控制**：平铺的卡片模块默认取消阴影（`shadow="never"`），仅在浮出层（Dialog, Dropdown）使用轻量级阴影。

## 4. 全局布局设计 (Global Layout)

采用经典的上下结构。

### 4.1 顶部导航栏 (Header)
*   **高度**：固定 60px，置顶。
*   **视觉**：纯白底色，底部 1px `#E4E7ED` 分割线。
*   **结构划分**：
    *   **左侧 (Logo区)**：系统 Logo 图标 + 系统名称“仲裁员办案系统”（字体加粗，颜色 `#303133`）。
    *   **中侧 (主导航区)**：采用 `el-menu` 水平模式。包含“首页”、“我的案件”、“待办事项”、“个人中心”。选中项底部有 2px 主题色高亮条。
    *   **右侧 (用户操作区)**：显示当前登录用户姓名（例如“张三 仲裁员”）及头像/下拉箭头，提供“退出登录”等系统级操作。

### 4.2 主内容区 (Main Container)
*   占据 Header 下方的剩余屏幕空间。
*   页面主体内容设置最大宽度（例如 1440px）并水平居中，保证在超大宽屏下的阅读体验。

## 5. 首页功能区详细设计 (Dashboard Layout)

采用 **16:8** 的左右双栏栅格布局（左侧占总宽度的 2/3，右侧占 1/3），区块间距（Gutter）设为 20px。

### 5.1 左栏：主业务流区

#### 5.1.1 待办中心 (Todo Stats Widget)
*   **定位**：快速把握当前待办任务的全局概况，提供快捷跳转。
*   **展现形式**：横向排列的“数据汇总卡片”（Grid 布局）。
*   **数据项**：总待办数、待签承诺书、待签笔录、待审批延期、待签文书、待草拟裁决书。
*   **卡片样式**：浅灰底色小区块，左侧放置对应业务的线性图标，右侧为文字标题和突出的数字指标。
*   **交互**：鼠标悬浮时背景颜色微调（无阴影突变），点击整块区域路由跳转至“待办事项”的一级列表页。

#### 5.1.2 近期开庭 (Upcoming Hearings Widget)
*   **定位**：提醒即将到来的庭审任务。
*   **展现形式**：极简的数据表格（`el-table`）。
*   **字段包含**：案号、案由、开庭时间、庭室地址、状态标签（待开庭/已开庭）。
*   **表头**：使用灰色背景 `#F5F7FA` 以区分内容。
*   **头部操作**：右上角提供“查看全部”的文字链接。

#### 5.1.3 消息通知 (Notifications Widget)
*   **定位**：系统消息提醒与处理。
*   **展现形式**：精简的列表项。
*   **字段包含**：消息标题、接收时间、未读状态红点。
*   **头部操作**：提供“全部已读”和“清除缓存”的无边框文本按钮。

### 5.2 右栏：辅助工具区

#### 5.2.1 日程安排 (Calendar Widget)
*   **定位**：按月视图直观展示案件排期情况。
*   **展现形式**：引入 `el-calendar`，进行样式覆盖以达到极简效果。
*   **控制项**：仅保留“上月 / 本月 / 下月”的切换按钮。
*   **数据标注**：日期单元格内如果有待办或开庭，使用极小的品牌色圆点（Badge）标注，保持格子内部整洁。
*   **附属信息**：在日历组件下方，直接展示文字版“今日待办”和“今日到期案件”摘要。

#### 5.2.2 法律检索 (Legal Search Widget)
*   **定位**：快速对接北大法宝的检索入口。
*   **展现形式**：
    *   顶部提供类型切换：使用 `el-radio-group`（按钮样式）切换“法律法规”与“司法案例”。
    *   主体提供搜索输入框：带搜索图标的宽幅 `el-input`。
*   **交互说明**：本区块仅作为入口，输入关键词并触发搜索后，可跳转至专门的检索结果页或弹出抽屉展示，以维持首页的布局稳定。

## 6. 组件划分建议 (Component Architecture)

为了保证代码的可维护性，建议在 `src/views/home/` 目录下将页面拆分为以下粒度：

*   `HomeView.vue`：首页容器，负责栅格布局（`el-row`/`el-col`）和各组件的组装。
*   `components/TodoStats.vue`：待办数据卡片群。
*   `components/HearingList.vue`：近期开庭表格。
*   `components/NotificationList.vue`：消息通知列表。
*   `components/CalendarBoard.vue`：日历及今日提醒。
*   `components/LegalSearch.vue`：法律检索入口框。
