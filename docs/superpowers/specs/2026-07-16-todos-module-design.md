# PC仲裁员端重构 - 第二阶段设计规范（待办事项模块）

## 1. 概述 (Overview)

本文档定义"PC仲裁员办案系统重构"第二阶段的设计规范，聚焦于 **"待办事项"模块（P0级核心模块）**。该模块从"我的案件"中独立为一级模块，承担仲裁员日常签批、审批、核阅等高频任务处理的职责。

本设计沿用第一阶段确立的视觉基调与技术架构，与首页待办统计卡片形成业务闭环。

### 1.1 设计目标

- 将分散的签批任务（承诺书、笔录、文书、延期审批、裁决书草拟/核阅）按业务性质归类，提供清晰的任务处理入口
- 支持行内快速操作，减少页面跳转，提升办案效率
- 左栏菜单 + 数量徽标，让仲裁员一眼掌握各分类待办量

### 1.2 范围说明

| 内容 | 状态 |
|------|------|
| 签名列表（承诺书/笔录/文书） | 本期实现 |
| 待办中心（延期审批/草拟裁决书） | 本期实现 |
| 裁决书核阅列表 | 本期实现 |
| 智能约庭 | 本期仅保留入口占位，不实现排期逻辑 |
| 首页 TodoStats 跳转联动 | 本期实现（小改动） |

---

## 2. 信息架构 (Information Architecture)

首页待办统计的 6 类待办，按业务性质归类到待办事项模块的 4 个子菜单：

```
待办事项
├── 签名列表（承诺书签署 + 笔录签名 + 文书签名）
├── 待办中心（延期审批  + 选择首席仲裁员）
├── 裁决书核阅列表
└── 智能约庭 [建议]（占位）
```

**归类原则：** 将同属"签批确认"性质的承诺书、笔录、文书合并为"签名列表"；将需要仲裁员决策审批的任务（延期、选择首席仲裁员）归入"待办中心"；裁决书核阅因流程独立单独成列。

## 3. 路由与文件结构 (Routing & File Structure)

### 3.1 路由配置

采用嵌套路由，URL 可深链接、可书签：

```
/todos                    → TodosView.vue（容器，重定向到 /todos/signature）
  /todos/signature        → SignatureList.vue（签名列表）
  /todos/center           → TodoCenter.vue（待办中心）
  /todos/review           → ReviewList.vue（裁决书核阅列表）
  /todos/scheduling       → SchedulingView.vue（智能约庭-占位）
```

默认进入 `/todos` 时重定向到 `/todos/signature`（签名列表为最高频操作）。

### 3.2 文件目录

```
src/views/todos/
  TodosView.vue              # 容器：左栏菜单 + 右栏 router-view
  components/
    SignatureList.vue        # 签名列表（承诺书/笔录/文书）
    TodoCenter.vue           # 待办中心（延期审批/选择首席仲裁员）
    ReviewList.vue           # 裁决书核阅列表
    SchedulingView.vue       # 智能约庭占位页
    shared/
      TodoFilterTabs.vue     # 复用的筛选标签栏组件
      TodoEmptyState.vue     # 复用的空状态组件
```

## 4. 整体布局 (Layout)

采用左右双栏布局。

### 4.1 左栏菜单（el-menu 垂直模式）

- **宽度**：固定 200px，纯白背景 `#FFFFFF`
- **分隔**：右侧 1px 边框 `#E4E7ED`
- **菜单项结构**：左侧线性图标 + 名称 + 右侧数量徽标（`el-badge`，品牌色 `#053d99` 背景圆点/数字）
- **选中态**：左侧 3px 主题色高亮条 + 浅色背景 `#f2f5fa`，文字加粗为主题色
- **"智能约庭"项**：名称后追加 `[建议]` 灰色小字标签，表明为占位功能

### 4.2 右栏内容区

- **背景**：页面灰底 `#F0F2F5`，内容以白色卡片承载
- **顶部工具栏**：页面标题（当前子模块名称）+ 筛选标签栏 + 搜索输入框
- **主体**：数据表格（`el-table`）+ 行内操作按钮
- **底部**：分页控件（`el-pagination`，支持每页 5/10/20 条 + 页码跳转）

### 4.3 交互行为

- 左栏菜单选中状态与当前 URL 同步（通过 `router.push` 实现）
- 左栏徽标数字由 Pinia store 统一管理，列表操作完成后实时更新

## 5. 各子模块列表详细设计

### 5.1 签名列表（SignatureList.vue）

**合并任务：** 承诺书签署 + 笔录签名 + 文书签名

**显示方式：** 承诺书签署 + 笔录签名 + 文书签名为tab标签页，点击tab切换显示对应列表

**筛选项：** 案件编号、当事人、类型、经办秘书、状态（待签名、已签名）

**表格字段：**

| 列名 | 说明 | 交互 |
|------|------|------|
| 案号 | 案件编号 | 点击跳转案件详情页 |
| 案由 | 案件事由简述 | 纯展示 |
| 申请人 | 申请人姓名/名称 | 纯展示 |
| 被申请人 | 被申请人姓名/名称 | 纯展示 |
| 标的（元） | 案件的标的金额 | 纯展示 |
| 经办秘书 | 案件经办秘书 | 纯展示 |
| 仲裁庭 | 案件仲裁庭成员 | 纯展示 |
| 案件状态 | 案件状态 | 纯展示 |
| 提交时间 | 办案秘书提交时间 | 纯展示 |
| 操作 | 「签名」按钮 | 弹窗确认 |

**承诺书签署操作流程：**
1. 点击「签名」→ 弹出 `el-dialog`
2. 弹窗内容：承诺书正文全文预览 + 底部签名区域
3. 点击底部签名区域：显示整个屏幕的签名区域
4. 确认签名后：`ElMessage.success` 提示 → 该行从列表移除 → 左栏徽标数字减一

**笔录签名操作流程：**
1. 点击「签名」→ 弹出 `el-dialog`
2. 弹窗内容：手写签名区域占满整个屏幕
3. 底部操作：「取消」/ 「清除」 / 「确认签名」
4. 确认签名后：`ElMessage.success` 提示 → 该行从列表移除 → 左栏徽标数字减一

**文书签名操作流程：**
点击签名按钮，提示：该功能暂未开放--后续实现


### 5.2 待办中心（TodoCenter.vue）

**合并任务：** 延期审批 + 选择首席仲裁员 + 其他综合待办

**显示方式：** 延期办理 + 选择首席 为tab标签页，点击tab切换显示对应列表

**筛选项：** 案件编号、当事人、类型、经办秘书

**辅助操作：** 延期办理支持一键同意功能

**表格字段：**

| 列名 | 说明 | 交互 |
|------|------|------|
| 案号 | 案件编号 | 点击跳转案件详情页 |
| 案由 | 案件事由简述 | 纯展示 |
| 申请人 | 申请人姓名/名称 | 纯展示 |
| 被申请人 | 被申请人姓名/名称 | 纯展示 |
| 标的（元） | 案件的标的金额 | 纯展示 |
| 经办秘书 | 案件经办秘书 | 纯展示 |
| 仲裁庭 | 案件仲裁庭成员 | 纯展示 |
| 组庭日期 | - | 纯展示 |
| 裁决期限 | 年/月/日（天数倒计时）（是否中止）（延期次数） | 纯展示 |
| 案件状态 | 案件状态 | 纯展示 |
| 提交时间 | - | 纯展示 |
| 操作 | 按任务类型不同 | 见下 |

**操作按任务类型区分：**
- **延期审批**：「审批」按钮 → 弹出 `el-dialog`，展示案号、延期原因、申请延期天数 + 「同意」/「驳回」按钮。操作后该行移除，徽标更新。
- **草拟裁决书**：「前往草拟」按钮 → 跳转至案件详情页的文书智能生成板块（路由跳转，不在列表内完成）。

### 5.3 裁决书核阅列表（ReviewList.vue）

**表格字段：**

| 列名 | 说明 | 交互 |
|------|------|------|
| 案号 | 案件编号 | 点击跳转案件详情页 |
| 案由 | - | 纯展示 |
| 申请人 | - | 纯展示 |
| 被申请人 | - | 纯展示 |
| 提交人 | 办案秘书姓名 | 纯展示 |
| 提交时间 | - | 纯展示 |
| 操作 | 「核阅」按钮 | 弹窗预览 |

**核阅操作流程：**
1. 点击「核阅」→ 弹出大尺寸 `el-dialog`（宽度 80%）
2. 弹窗内容：裁决书正文全文预览（可滚动）
3. 底部操作：「通过核阅」（主按钮） / 「退回修改」
4. 操作后该行移除，徽标更新。

### 5.4 智能约庭（SchedulingView.vue）- 占位

居中空状态展示：
- 图标（日历/排期类线性图标）
- 标题文字："智能约庭功能开发中，敬请期待"
- 说明文字："未来将支持自动匹配仲裁员排期、庭审场地空闲时段，避开冲突，一键生成排期表。"

## 6. 组件职责与数据流 (Component Architecture & Data Flow)

### 6.1 组件职责

| 组件 | 职责 | 对外接口 |
|------|------|----------|
| `TodosView.vue` | 布局骨架，渲染左栏菜单 + 右栏路由出口；挂载时拉取 counts | 菜单切换 → `router.push` |
| `SignatureList.vue` | 签名任务表格 + 筛选 + 签名弹窗 | 内部完成签批操作 |
| `TodoCenter.vue` | 综合任务表格 + 筛选 + 审批弹窗 / 草拟跳转 | 内部完成审批；草拟跳转外链 |
| `ReviewList.vue` | 核阅表格 + 核阅弹窗 | 内部完成核阅 |
| `SchedulingView.vue` | 占位空状态 | 无 |
| `shared/TodoFilterTabs.vue` | 复用筛选标签栏 | props: `tabs`数组; v-model: 当前选中 |
| `shared/TodoEmptyState.vue` | 复用空状态 | props: `text`, `icon` |

### 6.2 Pinia Store（`stores/todo.js`）

集中管理待办数据，使左栏徽标与各列表数据同源：

```js
// 核心状态
{
  counts: {
    signature: 8,   // 签名列表待办数
    center: 2,      // 待办中心待办数
    review: 1       // 裁决书核阅待办数
  },
  signatureList: [...],
  todoCenterList: [...],
  reviewList: [...]
}

// 核心方法
fetchAllCounts()                  // 拉取各分类数量（左栏徽标）
fetchSignatureList(filter)        // 拉取签名列表（支持类型筛选）
fetchTodoCenterList(filter)       // 拉取待办中心列表
fetchReviewList()                 // 拉取核阅列表
signDocument(id)                  // 完成签名 → 更新列表 + counts
approveExtension(id, action)      // 审批延期（action: 'approve'|'reject'）
reviewAward(id, action)           // 核阅裁决书（action: 'pass'|'reject'）
```

### 6.3 数据流

```
TodosView 挂载
  → store.fetchAllCounts()
  → 左栏菜单徽标渲染

点击左栏菜单项
  → router.push('/todos/xxx')
  → 子组件挂载
  → store.fetchXxxList()
  → 表格渲染

行内操作（签名/审批/核阅）
  → store.signDocument / approveExtension / reviewAward
  → 更新对应列表数据
  → 重新计算 counts
  → 左栏徽标 + 表格同步刷新
```

**当前阶段使用 Mock 数据：** 所有 store 方法返回本地静态/模拟数据。后续对接真实 API 时，只需替换 store 方法内部实现，组件层无需改动。

## 7. 视觉规范 (Visual Consistency)

沿用第一阶段首页确立的设计约束，确保全站一致性。

| 项目 | 规范 |
|------|------|
| 卡片容器 | 白底 `#FFFFFF`、1px 边框 `#E4E7ED`、4px 圆角、`shadow="never"` |

| 筛选标签 | `el-radio-group` 按钮样式，选中态主题色 `#053d99` |
| 任务类型 Tag | Element Plus 内置 Tag type（primary/success/warning/info） |
| 操作按钮 | `el-button` link 类型，主题色，无背景填充 |
| 分页 | `el-pagination`，支持每页条数选择（5/10/20）+ 页码跳转 |
| 品牌色 | Primary `#053d99`、Dark `#00296b`、浅色区块 `#f2f5fa` |

## 8. 边界情况处理 (Edge Cases)

| 场景 | 处理方式 |
|------|----------|
| 列表无数据 | `TodoEmptyState` 组件：图标 + "暂无待办事项"文案 |
| 加载中 | `el-table` 的 `v-loading` 指令，品牌色 spinner |
| 操作成功 | `ElMessage.success` 轻提示，列表刷新，左栏徽标更新 |
| 操作失败 | `ElMessage.error` 错误提示，列表不变 |
| 搜索/筛选无结果 | 表格内显示"暂无匹配数据"空状态 |
| 分页超出范围 | 自动回到最后一页 |

## 9. 首页联动改动 (Home Page Integration)

首页 `TodoStats.vue` 的 6 个待办卡片，点击后根据类型跳转到对应子路由，形成业务闭环：

| 首页卡片 | 跳转目标 |
|----------|----------|
| 总待办 | `/todos`（默认重定向到签名列表） |
| 待签承诺书 / 待签笔录 / 待签文书 | `/todos/signature` |
| 待审批延期 / 待草拟裁决书 | `/todos/center` |

此改动仅涉及 `TodoStats.vue` 中各卡片的 `path` 属性调整，不涉及组件结构变化。
